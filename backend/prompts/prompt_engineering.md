# 提示词工程配置手册

> 这个文件就是整个项目的**提示词约束中心**。
> 修改它即可扩展角色类型、风格、时代背景和硬性规则，**不需要改任何代码**。
> 保存后下一次生成任务自动生效（服务端按文件修改时间热加载）。

---

## 怎么用

想生成新的类型（比如现代都市、赛博朋克、日系动漫风），只需做两件事：

1. 在「五、风格预设」里**加一种风格**（复制现有风格改一改）
2. 如果身份体系也要换（比如不要"贵族/仙人"，要"学生/上班族/机械师"），在「三、身份设定」里**替换身份**

其余约束（背景、构图、鞋子、颜色、质量词）在「一、全局设定」里统一改。

> ⚠️ 编辑规则
> - 只改 `yaml` 代码块里的**内容**，不要动结构（缩进、减号、冒号）
> - 缩进必须用**空格**，不要用 Tab
> - 列表项写成 `- 值` 或 `[值1, 值2]`
> - 中英文冒号都可以，解析时会自动归一化
> - 保存前建议先在页面点「校验」，确认能被正确解析

## 一、全局设定

决定了出图的**底层规则**：画面背景、构图、鞋履禁令、质量词等。

```yaml
# 世界观：影响给大模型的人设与文案
世界观: 中国古代
服饰专家人设: 精通中国古代服饰史的顶级设计师
服饰种类词: 古装

# 出图固定前缀（写进英文提示词开头）
背景与构图: pure white background, full body shot, front view, standing pose

# 固定质量尾缀（写进英文提示词结尾）
质量词: masterpiece, best quality, 8k ultra detailed

# 鞋履规则（服饰阶段 + 翻译阶段都会强制执行）
鞋履规则: 必须全包脚、不露脚趾、平底无后跟；严禁运动鞋、高跟鞋、皮鞋、凉鞋、木屐

# 时代/背景名词（"朝代"可换成"纪元""时代""地域"等）
时代名词: 朝代

# 服饰阶段强制约束（逐条注入提示词）
硬性要求:
  - 绝对禁止与现代世界观冲突的元素（如古装世界观下的运动鞋、拉链、眼镜框等）
  - 配色严格使用指定主色与配色，严禁出现第三种服装主色
  - 体型必须在服饰描述中显式体现剪裁关键词
  - 所有元素必须符合所选风格的整体审美
  - 性别严格匹配，严禁出现异性特征

# 服饰阶段输出字段（字段名即 JSON key，代码按名读取，增删改字段名需同步代码）
输出字段:
  朝代: 具体时代或地域，如 唐代
  服装描述: 详细描述，包含上衣款式、下装、外罩、面料质感、纹样刺绣、配饰细节，必须符合所选风格，80-120字
  鞋子描述: 鞋履详细描述，包含款式名称、颜色、材质、装饰纹样，30-40字，必须全包脚不露趾+平底无后跟
  发型描述: 发型详细描述，必须包含①具体髻式名称+位置/结构描述 ②簪钗步摇等配饰及材质颜色 ③发色发质描述，40-50字，每个角色发型结构要不同
  面部特征: 根据性别和年龄生成，必须包含①脸型②眼型③眉形④鼻型⑤唇形⑥肤质年龄特征，40-50字，五官组合必须不同
  光影氛围: 符合所选风格的光影描述，要有创意变化，20-30字
  特殊细节: 针对该身份与风格的独特设计元素，30-50字
  气质关键词: 3-5个形容角色气质的词汇，必须符合身份气质，严禁出现与身份不符的词
```

## 五、风格预设

风格决定了气质、配色、姿势、光影、细节程度。
**新增风格：复制下面任意一段，改名并调整各项即可。**

```yaml

    光影: 明亮但柔和的自然光，突出人物立体感，背景纯净
```

## 常见问题

**Q：改了没生效？**
保存后点页面上「校验并保存」，再重新生成一次。服务端按文件修改时间热加载，无需重启。

**Q：改坏了能恢复吗？**
可以。页面上有「恢复默认」，会用内置默认配置覆盖当前文件（会先自动备份一份）。

**Q：新增身份后，导出 Excel 会报错吗？**
不会。`地位` 的校验集合来自本文件的「三、身份设定」，新增身份会自动纳入校验。但数据库字典表（若已建表）需要同步插入新值。

**Q：风格名可以随便起吗？**
可以。生成后会作为文件名的一部分（`generated_prompts_{风格名}_{日期}_{时间}.json`），建议避免特殊符号。
